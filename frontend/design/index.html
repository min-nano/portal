デザインシステム

表示:

このポータルの画面を組み立てるための、色・寸法・部品の決めごとです。 実際のツールと同じ CSS（src/styles.css）をそのまま読み込んで並べているので、 ここに出ているものが、そのまま画面に出るものです。

1. 考え方（この 3 つだけ守る）

① 画面は「入力する面」「読む面」「操作するもの」の 3 つでできている

入力する場所は必ず枠のある升目（--field-bg）にして、周りの下地 （--surface-sunken）と区別します。読むもの（計算結果）は白い枠の中に置き、 数値は等幅・右そろえにします。操作するものはボタンだけで、主・副・削除の 3 段階しかありません。 文字の濃さや余白で「何となく」分けるのではなく、面の色で分けます。

② 緑と赤は判定にしか使わない

OK / NG の色を、ボタンや飾りに使いません。画面の中で緑か赤が見えたら、それは必ず 「計算結果の判定」です。判定は升目（.verdict）・行・結果の節の見出しの帯の 3 段階で同じ色になるので、表を読まなくても NG の有無が分かります。

③ 広い画面で増えた幅は、説明文ではなく入力欄に使う

ページの幅は 1280px まで広げますが、説明文は 68 文字程度で頭打ち（--prose-max）にします。 増えた幅は「入力欄を横に並べる」「結果を右の列に貼り付ける」ために使います。

こうする

関係する欄（幅・高さ・ピッチ）は横に並べる。単位は欄にくっつける。 結果は入力の右に置いて、直しながら数字の変化を見られるようにする。

こうしない

1 行 1 欄で下へ延々と積む。ボタンを全部同じ幅・同じ色にする。 結果を画面のいちばん下に置いて、入力のたびにスクロールさせる。

2. 色

画面側の CSS には生の色を書きません。使うのは「役割の名前」だけです （src/styles/tokens.css）。明るい／暗いテーマの切り替えは light-dark() で 1 か所にまとまっていて、部品側の CSS は 1 行も変わりません。 右上の「テーマ」で切り替えて確かめられます。

5. 入力欄

入力する場所は、どのツールでも同じ形にします。ラベルは太字の小さめ、欄は白い升目、 単位は欄の右に地続きで付けます（「どこまでが mm の欄か」が読めるように）。 高さは --tap（44px）以上、文字は 16px で、スマートフォンで触れたときに 画面が勝手に拡大しません。必須の札は、値が右そろえになる数値の欄では枠の中の左側 （右は値と単位で埋まるため）、それ以外の欄ではラベル行の右端に置きます。

mm

数値は右そろえなので、札は左側に付きます。

左寄せの欄では、札はラベル行の右端に付きます。

前提を満たすまで入力できない欄は、灰色にして理由を添えます。

選択肢

文字だけのラジオ・チェックは押す場所が狭く、選び間違えます。行ごと押せる札にして、 選んだものは下地と枠で残します。

6. ボタン

3 段階しかありません。主（塗り）はその画面で 1 つだけ、 副（枠線）はいくつでも、削除（赤い枠線）は塗りません （押し間違いが取り返しにくいので、塗って目立たせるのではなく、他と違う形にします）。

「＋ 追加」は破線の枠にして、「ここに増やせる」ことを形で示します。 Excel 出力・保存のような、そのページの目的そのものにあたるボタンだけを塗ります。

7. 節（折り畳めるカード）

入力のかたまりは 1 枚のカードです。見出しの行はどこを押しても開閉でき、 閉じているあいだも見分けが付く情報（面材名・部屋名）は見出しに残します。 この見本ページ自身も同じ部品でできています。

9. 待たせるとき（読み込み中）

画面を開いてから使えるようになるまでには、①サインインの確認（Clerk の読み込みと セッションの問い合わせ）と、②ツールの準備（フォーム定義の取得と、計算実装（wasm）の 読み込み）の 2 段があり、合わせて数秒かかることがあります。そのあいだ何も出ないと 「壊れている」ように見えるので、待たせるなら必ず見せるを決めごとにします。

JS を待たずに出す

いちばん長く待つのは JS そのものの読み込みなので、読み込み中の表示を JS で作ると 間に合いません。回る輪は CSS の擬似要素だけで描き（.page-loading）、 文言は HTML に直接書きます。こうすると、スクリプトを 1 行も読む前――HTML と CSS が 届いた時点――で出ます。

サインインを確認しています…

文言は「何を待っているか」を書きます（「読み込み中」だけだと、待っているのが 画面なのか計算なのか分かりません）。段が変わったら setPageLoadingLabel() で言い換えます （「サインインを確認しています…」→「計算の準備をしています…」）。 role="status" が付くので、文言が変わったことは読み上げにも伝わります。

速く終わるときは見せない

キャッシュが効いていて一瞬で終わる読み込みでは、輪が光って消えるちらつきだけが 残ります。そこで、出るのを --wait-visible（0.2 秒）だけ遅らせます。 それより早く終われば、何も見えないまま画面が出ます。 動きを減らす設定（prefers-reduced-motion）のときは回さず、 濃さをゆっくり変えて「動いている」ことだけを残します。

画面を出すのは「入力できるようになった時点」

組み立て途中のフォームは見せません。空の選択肢や、まだ並んでいない入力欄が 一瞬映ると、それ自体が壊れて見えるためです。ページ本体（#app）は hidden のまま始め、フォームを組み立て終えたところで showApp() を呼びます（画面が出て、読み込み中の表示が消えます）。 失敗して先に進めないときも必ず呼びます。理由を出す場所 （#message）が画面の中にあるからで、回り続けたまま終わる画面を 作らないためでもあります。

#pageLoading ページの読み込み中。各ページの HTML に置き、showApp() で消える
setPageLoadingLabel() 待っているものが変わったときに文言を言い換える（表示は消さない）
showApp() 画面（#app）を出して、読み込み中を消す。入力できるようになった時点で呼ぶ
ゲートの中 サインイン画面（@clerk/ui）は未サインインだと分かってから読み込むので、 マウント先にも同じ表示を置く。Clerk が描いたら消える
--wait-visible 出すまでの間（0.2 秒）。これより早く終わる読み込みでは見せない
--dur-spin回る輪の 1 周（0.9 秒）

10. 骨組み（広い画面と狭い画面）

ページの最大幅は --shell-max（1280px）。1080px 以上では、入力（左）と 結果（右）の 2 列になります。.has-dock を付けた要素の中で、 .result-dock だけが右の列に移り、スクロールしても貼り付いたまま残ります。 DOM の並びは変えていないので、読み上げ順とタブ順は「入力 → 結果」のままです。

結果（.result-dock）

狭い画面では 1 列に戻り、結果は入力の下に流れます。そのままだと判定が画面の外に 出てしまうので、右下に「結果へ飛ぶ」ボタンを出し、そのボタンの色でも NG の有無が分かるようにしています（このページの右下にも出ています）。

画面に貼り付く帯（ヘッダー・壁の切り替えなど）を足すときは、2 列になる広さで 右の列に重ならないことを確かめてください。全幅のまま貼り付けると、結果の見出しを 覆い隠します（壁の切り替えの帯は、2 列のときは入力の列の幅までにしています）。
