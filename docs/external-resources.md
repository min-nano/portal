# 事務所オリジナルの係数とロジックを、リポジトリの外から差し込む

**このリポジトリは公開です。** そのうえで、見積書・契約書等の作成ツールには
**事務所が独自に決めた係数・積算のロジック・書類の書式**が入ります。**そこだけを
非公開にし、リポジトリの外（Drive）で管理して差し込めるようにする**のが本書の設計です。

対象は土台（`portal_sdk`）で、特定のツールの設計ではありません。
これに載る最初のツールの設計は [contract-formatter.md](contract-formatter.md) にあります。

> **まだ実装していません。** 実装の順序は §12 にあります。

---

## 1. 線引き — 法令に書いてあることと、事務所が決めたこと

**隠すべきものと、隠す必要のないものを混ぜません。**

| | 置き場所 | 見えてよいか |
| --- | --- | --- |
| **法令・告示に書いてあること**（別表の値、費目の構成、難易度係数、法定記載事項、適用範囲） | **リポジトリ**（公開） | **見えてよい。** 官報と e-Gov で誰でも読めるものを隠しても、得るものが何もない |
| **事務所が決めたこと**（独自の係数・補正・積算の手順・値引きの根拠・書類の書式と文言・雛形） | **Drive**（非公開） | **見せない。** ここが事務所の中身そのもの |
| 事務所の設定値（単価・税率・端数処理） | Firestore（非公開） | 見せない |

**利用者（サインインできる事務所の人間）には、どちらも見えてよい**ことにします。
**隠す相手はリポジトリの読み手**であって、使う本人ではありません。
この 1 行が、後の設計をずいぶん簡単にします（§10）。

> **リポジトリに値を 1 つも置かない、という作りにはしません。** それをやると
> **告示の別表の転記が正しいことを CI で守れなくなります。** 別表は公開情報なので、
> **リポジトリに置いて原文と突き合わせるテストで固定するほうが、明らかに安全**です。

## 2. 二層にする — 土台（公開）に、重ね（非公開）を載せる

```
  リポジトリ（公開）                    Drive（非公開。事務所が管理する）
  ────────────────────────           ──────────────────────────────
  土台のルール                          重ね（オーバーレイ）
    告示の別表・難易度係数        ←載る──  独自の係数・表
    費目の構成・略算方法の手順             独自の手順（加算・値引き・最低報酬）
    適用範囲のガード                      書類の書式・文言・雛形の対応
    法定記載事項のキーと必須条件           事務所固有の項目
    ─────────────────                 ─────────────────
    式の評価器（core/）                  ↑ 検証して「発行」したものだけが効く
```

| | |
| --- | --- |
| **土台（base）** | リポジトリ同梱。**告示・法令をそのまま写したもの**。改正への追従は**コードのレビューを経る**（そうあるべきものです） |
| **重ね（overlay）** | Drive で編集し、検証して**発行**する。**コードの変更もデプロイも要らない**（単価の見直しや文言の修正が、リリースを待たない） |

**土台も重ねも、同じ形式・同じ評価器で動きます。** 二重の仕組みを持ちません。

## 3. 置き場所 — 3 つに分ける

```
  Drive（原本。人が編集する）            Firestore（発行済み。実行時に読む）      リポジトリ（公開）
  ────────────────────────────         ──────────────────────────────────     ──────────────────
  設定フォルダ/                          tool_resources/<ツール>                 土台のルール
    overlay.json          ──[発行]──→     published_hash ─┐                     式の評価器（core/）
    fee-overlay.json                      revisions/<hash>┘ ←── 実行時はここだけ  画面
    契約書.gdoc  ────────────────────────────────────────→ 生成時に本人の代理で複製
```

| 置き場所 | 何を | なぜそこか |
| --- | --- | --- |
| **Drive の設定フォルダ** | 雛形（Google ドキュメント / xlsx）と、重ねの JSON | 人が編集し、版履歴が残り、共有設定で権限が決まる。**すでに雛形でそうしている**（`excel-report-formatter`） |
| **Firestore** | **発行済みの重ね**（中身そのもの）と、どの版を使うかの目印 | 実行時に人の編集が直接効かない。Drive を叩かないので速く、Drive が落ちても書類が作れる |
| **リポジトリ** | 土台のルール・評価器・画面・**ダミーの重ね** | 事務所固有のものを持たない |

**Drive と Firestore の役割が違うことが要点です。** Drive は**編集する場所**、
Firestore は**実行する版**。あいだに「発行」という人の操作が入ります（§4）。

> **雛形（Google ドキュメント）だけは Drive に残ります。** Docs API の置換は Drive 上の
> ファイルに対して行うためです。したがって**雛形の取得は今までどおり実行ユーザー本人の
> 代理で行われ、本人に閲覧権限が無ければ失敗します。**

## 4. 発行（publish）— Drive の編集を、そのまま本番にしない

```
[設定] → Drive のフォルダを選ぶ（Picker）
       → [読み込んで検証]  … 読み込み、土台と合成し、検証し、前の版との差分を出す
       → 検証の結果を見る  … 項目数・自己テストの結果・雛形の照合・合成できなかったもの
       → [発行]            … Firestore へ格納し、目印を新しいハッシュへ向ける
```

| 決めごと | なぜ |
| --- | --- |
| **実行時は Firestore の発行済み版だけを読む。Drive を見ない** | Drive での編集途中・保存ミス・誤削除が本番へ即座に出ない。**「設定を直したら書類が作れなくなった」を構造的に起こさない** |
| **発行の単位はフォルダ全体で、版はハッシュ 1 つ** | 「書式は新しい版、係数は古い版」という組み合わせを作らない。**再現するときに指すものが 1 つで済む** |
| **発行できるのは、その設定フォルダに Drive の編集権限を持つ人だけ** | 権限を portal 側に作らない。**境界は Drive の共有設定**という portal の作法（README「セキュリティ / 権限モデル」）のまま |
| **前の版へ戻せる** | 発行済みの版は消さずに残す（`revisions/<hash>`）。戻すのは目印を旧ハッシュへ向けるだけ |
| **検証に落ちた内容は発行できない** | 壊れた設定が本番に出る経路を無くす。落ちた理由は**どのファイルの、どのキーか**まで出す |

### 発行時に検証すること

| # | 検証 | 落ちたときの意味 |
| --- | --- | --- |
| 1 | **スキーマ**（必須キー・型・重複キー・未知のキー） | 書き間違い |
| 2 | **土台との合成**（差し込む先が実在するか。§6 の禁じ手に触れていないか） | 土台の改訂で、差し込む先が無くなった |
| 3 | **参照の解決**（項目が指す雛形・プレースホルダー・表・設定値が存在するか） | 消し忘れ・打ち間違い |
| 4 | **式の静的検査**（未知の識別子と関数、循環参照、ノード数と深さの上限、定数 0 での除算、出力が丸めを通っていること） | 計算が実行時に壊れる形になっている |
| 5 | **表の形**（軸が単調増加・欠測なし・行の長さが揃っている） | 転記の抜け |
| 6 | **自己テスト**（重ねが持つ期待値を、合成後のルールで流す。§8） | **独自の係数・手順の間違い** |
| 7 | **雛形の照合**（Docs API で本文を読み、必須項目のプレースホルダーが実在するか） | 雛形と定義がずれている |
| 8 | **大きさ**（Firestore の 1 ドキュメント上限 1 MiB に収まるか） | 分割が要る（§5） |

**7 が効きます。** 従来は「生成しようとして初めて雛形のずれに気付く」でしたが、
**発行の時点で分かります。** 雛形は発行後も編集できてしまうので、生成時の
`occurrencesChanged` による検証（[contract-formatter.md](contract-formatter.md) §4.3）は残します。

## 5. 実行時 — 何を、どう読むか

```
要求 → 目印（tool_resources/<ツール>）を読む → published_hash
     → revisions/<hash> を読む → 土台と合成 → 評価器へ
```

| 決めごと | なぜ |
| --- | --- |
| **版（`revisions/<hash>`）はプロセス内で無期限にキャッシュする** | ハッシュで名前が付いているので**中身が変わらない**。変われば別の名前になる |
| **合成の結果もハッシュで覚える**（重ねのハッシュ ＋ 土台の版） | 合成は毎回やらない。**土台が変わる（デプロイ）と自動的に別の名前になる** |
| **目印は短い期間だけキャッシュする（60 秒）** | 発行してから全インスタンスに行き渡るまでの時間を、この一言で説明できるようにする |
| **JSON は正規化して gzip で格納する**（Firestore の bytes 型。base64 にしない） | 正規化（キーの並び順・空白）を決めるのは、**同じ内容が常に同じハッシュになる**ようにするため |
| **1 MiB を超えるときは発行時に分割する**（`revisions/<hash>/parts/<n>`） | 実行時は連結するだけ。**上限に当たったことが発行の時点で分かる** |
| **未発行なら 409** | 「設定が発行されていません。管理者が『設定』から発行してください。」既存の雛形未設定と同じ扱い |
| **スキーマの major が合わなければ 409** | 土台を更新したのに古い重ねが残っている、を黙って動かさない。文面で「発行し直してください」と出す |

**画面にも合成後のルールが要ります。** フォームを組み立て、入力のたびに金額を出すのは
画面側だからです。`GET /api/tools/<id>/config` が配ります（既存の `form_config()` の作法）。

> **重ねをビルドに焼き込みません。** フロントエンドの静的ファイルは Firebase Hosting が
> **サインインしていない相手にも配ります。** 認証の要る API から配ることが、
> 非公開の条件そのものです。**土台のほうは公開なので、wasm に焼き込んで構いません。**

## 6. 重ねの形 — 何を、どこに差し込めるか

**これが本書の中心です。** 重ねは「上書きするファイル」ではなく、
**土台に対する差し込みの指示**です。

```jsonc
// 形を示すための架空の例。実在の費目・値ではない
{
  "schema": "portal.overlay/1",
  "extends": "…",                       // どの土台に載せるか
  "set":    { "…": 0 },                 // 事務所の設定値（Firestore にある値の既定）
  "tables": { "own_a": { /* … */ } },   // 独自の表
  "steps": [
    { "id": "own_b", "after": "…", "label": "…", "expr": "step.… * lookup(own_a, in.…)" }
  ],
  "guards":    [ { "when": "…", "message": "…", "mode": "block | warn" } ],
  "print":     [ { "step": "own_b", "label": "…" } ],
  "selftests": [ { "in": { /* … */ }, "expect": { /* … */ } } ]
}
```

| 差し込めるもの | 書き方 |
| --- | --- |
| 土台の選択 | `extends` |
| 事務所の設定値 | `set`（実際の値は Firestore。ここに書くのは既定と、要求するキーの宣言） |
| **独自の表** | `tables` |
| **独自の手順**（加算・値引き・最低報酬・独自の端数処理） | `steps` に `after` / `before` で挿入位置を指定 |
| **独自のガード**（受注条件・警告） | `guards` |
| **内訳書に出す行と文言** | `print` |
| **書式**（事務所固有の項目・並び・文言・雛形とプレースホルダーの対応） | `documents` / `fields` |
| 土台に無い業務のルール**丸ごと** | `extends` を書かず、`steps` を最初から書く |

### 差し込めないもの（禁じ手）

**発行時に落とします**（§4 の検証 2）。

| 禁じ手 | なぜ |
| --- | --- |
| **告示の別表・難易度係数の値を書き換える** | **「告示による算定額」が説明できなくなります。** 事務所の判断は**別の行として重ねる**もので、告示の値そのものを差し替えるものではありません |
| **「告示による算定額」より前の手順を差し替える** | 同上。**告示が事務所に委ねている値**（人件費単価・倍数の調整・技術料等経費率）は `set` で与えられるので、手順を触る必要がありません |
| **土台が必須にしている記載事項を、任意に緩める** | 法定記載事項を落とした書面が作れてしまいます。**厳しくする方向（任意 → 必須）は通します** |

```
      土台の手順 ────────────────→ 告示による算定額 ──→ 重ねの手順 ──→ 提示額
      ↑ 差し替え不可                  ↑ ここが境界        ↑ ここから自由
      （set で値を与えるだけ）
```

**この境界は、内訳書の「告示による算定額」と「提示額」を分ける方針
（[contract-formatter.md](contract-formatter.md) §6.7）と同じ線です。**
**書面で分けて印字するものを、計算でも分けて持ちます。**

> **告示の対象外の業務**（調査・鑑定・検査・手続の代理）には土台がありません。
> **その場合は重ねだけでルールを丸ごと書けます。** 禁じ手は「土台があるものに載せるとき」
> の制約であって、**独自のものを作る自由を狭めるものではありません。**

## 7. 計算をデータで書く — 式と評価器

**評価器は `core/`（Rust → wasm）に置きます。** 画面とサーバーが同じ実装を動かす、という
既存の作法（必要壁量・面材張り大壁）をそのまま使えます。**土台のルールも wasm に焼き込む**
ので、**告示の値は画面とサーバーで必ず一致します。**

```
core/src/calc/
  expr.rs     # 式の構文解析と評価（純粋。I/O なし）
  table.rs    # 表引きと補間
  money.rs    # 有理数と丸め
  merge.rs    # 土台と重ねの合成（禁じ手の判定を含む）
  check.rs    # 発行時の静的検査
core/rules/
  <告示ごとのルール>.json   # 土台。原文からの転記。CI で原文と突き合わせる
```

### 式に書けるもの

| | |
| --- | --- |
| 参照 | `in.<キー>`（入力）・`set.<キー>`（設定値）・`step.<id>`（前の手順の値）・`<表名>.<行名>` |
| 演算子 | `+ - * /` `< <= > >= == !=` `&& \|\| !` |
| 関数 | `if` `min` `max` `abs` `sum` `product` `coalesce` `lookup` `interp` `round` |
| 上限 | ノード 512・深さ 32・手順 200・表の要素 20,000 |

**書けないもの**: 代入、ループ、再帰、関数定義、文字列の演算、外部参照。
**式は純関数で、同じ入力からは必ず同じ値が出ます。**

| 決めごと | なぜ |
| --- | --- |
| **数は有理数（分子・分母とも整数）で持つ** | 補間も税率も除算で分数になる。浮動小数点を使わないという既存の方針（`core/src/format.rs`）を、外から来る式でも守る |
| **丸めは `round` を書いた手順でだけ起きる** | どこで端数が消えたかが定義に書いてある状態にする。**出力が `round` を通っていることは発行時に検査する** |
| **失敗は 409（重ねの不備）で、500 にしない** | 壊れているのはコードではなく設定。**どの手順で落ちたか**を文面に出す |
| **評価器の側に既定値を持たない** | 「設定が無ければ 1.0」のような親切を入れると、**どこから来た値か分からない金額**が出る。未定義は未定義として発行時に落とす |

> **公開された評価器が非公開のデータを読む**という形の安全性は、
> 「式に I/O が無い」「ループが無い」「上限がある」「静的検査を通ったものしか発行できない」
> の 4 つで担保します。重ねを書けるのは事務所の管理者だけですが、
> **壊れた式で落ちないことは評価器の責任**です。

## 8. 正しさを、どこで守るか

**二層にしたので、守る場所も二層になります。**

| | どこで | 何を |
| --- | --- | --- |
| **土台** | **公開 CI** | **告示の別表・難易度係数が原文と 1 つも違わないこと**（表を丸ごと突き合わせる）。費目の構成・適用範囲・略算方法の手順 |
| **評価器** | **公開 CI** | 表引き・補間・丸め・条件・上限・エラー・**合成の禁じ手**（ダミーの重ねで固定する） |
| **重ね** | **発行時** | **重ねが持つ自己テスト**を、合成後のルールで流す。1 件でも合わなければ発行できない |

**リポジトリに値が戻ったことで、いちばん怖いもの（別表の転記ミス）を CI で守れます。**
事務所固有の係数と手順は CI では守れませんが、**自己テストが同じ役割を果たします**——
原本（社内規程・過去の見積り）と突き合わせるのは人の作業で、**その結果が自己テストとして
残り**、発行の記録に「自己テスト N 件 合格」として付きます。

> **CI に事務所の値を持ち込みません。** テストが使うのは
> `backend/tests/fixtures/overlay-sample/` の**架空の重ね**だけです。
> 実在の氏名・住所・金額を使いません。

## 9. 版の記録と再現性

**生成した PDF に、使った版を埋めます。**

```json
{ "rules": { "base": "…", "overlay": "…", "publishedAt": "…" }, "…": "…" }
```

- **土台の版**（リポジトリの版）と**重ねのハッシュ**の両方を持ちます。
  **どちらが変わっても、過去の書類がどの規則で作られたかを特定できます**
- PDF を開き直したとき、**現在の版と違えば画面に出す**（「この書類は別の版の設定で作られています」）
- **再計算はしません。** 金額は PDF に入っている値が正です
  （[contract-formatter.md](contract-formatter.md) §7 の「マスタを参照しない」と同じ理由）
- 監査で「この見積りはどの規則で出たのか」と問われたら、
  **土台はリポジトリの版から、重ねは `revisions/<hash>` から引けます**

## 10. 非公開の範囲

| | 見える相手 |
| --- | --- |
| 土台（告示・法令の写し）・評価器・スキーマ・画面 | **全員**（公開リポジトリ） |
| **重ね**（独自の係数・手順・書式・文言） | **サインインできる事務所の利用者**と、Drive で共有された人 |
| 雛形の本文（条項） | **Drive で共有された人だけ**（実行時も本人の代理で読むため） |
| 事務所の設定値 | サインインできる事務所の利用者 |

**重ねは、フォームの組み立てと金額の即時表示のために画面へ配られます。**
したがって**利用者は開発者ツールで中身を読めます。** 読める相手は事務所の人間で、
書類を作る当人なので、**これは受け入れます**（§1）。

**外部に対しては、リポジトリからも、サインインしていないブラウザからも、
重ねの中身に到達する経路がありません。**

> 利用者にすら見せたくない部分がある場合にだけ、`require_template_access` を立てます
> （`/config` を返す前に、雛形フォルダの閲覧可否を本人の代理で確かめる。Drive のメタデータ
> 取得 1 回）。**既定では立てません。** 使う人に見えない設定は、運用の事故のもとです。

## 11. 土台に足すもの

**ツールごとに書きません。** 土台に 1 つ置き、使うツールがそれを借ります
（[shared-logic.md](shared-logic.md) の作法。土台とツールのあいだに新しい層は作りません）。

```
backend/app/
  resource_store.py     # 発行済みの重ねの読み書き（Firestore）。settings_store.py と同じ位置づけ
  resource_bundle.py    # 束ね・正規化・ハッシュ・スキーマ検証・参照解決
  portal_sdk.py         # get_rules(tool_id) / publish_overlay(...) を足す
  google_drive.py       # フォルダ内のファイル一覧、capabilities（編集権限の確認）を足す
core/src/calc/          # 式の評価器と合成（§7）
core/rules/             # 土台のルール（公開。CI で原文と突き合わせる）
frontend/src/components/
  portal-resource-bar   # 「設定フォルダを選ぶ → 検証 → 発行 → 版を戻す」の画面部品
```

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET | `/api/tools/<id>/resources` | 発行状態（重ねのハッシュ・土台の版・日時・発行者・自己テストの結果） |
| POST | `/api/tools/<id>/resources/validate` | Drive の現在の内容を読んで**検証だけ**する（差分を返す。本番は変わらない） |
| POST | `/api/tools/<id>/resources/publish` | 検証して発行する（**Drive の編集権限が要る**） |
| POST | `/api/tools/<id>/resources/rollback` | 目印を過去のハッシュへ戻す |
| GET | `/api/tools/<id>/config` | 合成後のルールから導出したフォーム定義（既存の作法のまま） |

Firestore 上の位置（チャンネルの下。既存の `tool_settings` と並びます）:

```
static-channels/production/tool_resources/<ツール>                 ← 目印
static-channels/production/tool_resources/<ツール>/revisions/<hash> ← 中身（不変）
```

## 12. 環境と、既存のツール

| 環境 | 重ね |
| --- | --- |
| 本番（`static-channels/production`） | 事務所が発行した版 |
| 開発（`static-channels/development`） | **ダミーを発行して使う。** 本番の値をローカルへ持ってこない |
| PR プレビュー（`preview-channels/pr-<番号>`） | 空。画面は「未発行」の表示になる |
| CI | Firestore を使わない。ダミーの重ねをフェイク経由で流す |

**「本番の設定が無くても、CI もローカルも通る」ことが要件です。**
既定のチャンネルが development であること（`config.settings_channel_path()`）が
そのまま効き、**設定ミスの症状は必ず「未発行に見える」になります。**

既存の 4 つのツールは**移しません**。

| ツール | 今どこに | どうするか |
| --- | --- | --- |
| `excel-report-formatter` | 雛形は **Drive**（社外秘フォーマット）、定義は `mapping.json` | **雛形はすでに外。** 定義を移すかは、実際に困ったときに決める |
| `structural-cert-formatter` | 雛形は Drive、定義は `structural_cert_mapping.json` | **移さない。** 第四号書式は省令の様式 |
| `wall-quantity-calculator` | 表計算ツールを**同梱** | **移さない。** 誰でも配布ページから同じものを入手できる |
| `timber-panel-shear-calculator` | 計算は `core/`。グレー本の式 | **移さない。** 公刊物の計算法 |

> **先回りして一般化しません**（shared-logic §5）。土台に置くのは、
> **実際にそれを必要とするツールが 1 つ現れたとき**です。

## 13. 実装の順序

**どの段も単独で完結し、途中で止めても中途半端な状態は残りません。**

| | やること | 合否 |
| --- | --- | --- |
| **第 1 段** | **土台のルールの形と評価器**（`core/src/calc/`。ダミーの土台で、表引き・補間・丸め・条件・上限） | 画面とサーバーが同じ値を出す。上限とエラーが固定される |
| 第 2 段 | **合成と静的検査**（`merge.rs` / `check.rs`。**禁じ手の判定**を含む） | 禁じ手に触れた重ねが、場所つきの理由で落ちる |
| 第 3 段 | **束ねと検証**（`resource_bundle.py` ＋ スキーマ ＋ ダミーの重ね） | ダミーが検証を通り、壊したダミーが理由つきで落ちる |
| 第 4 段 | **発行と読み込み**（`resource_store.py` ＋ Firestore ＋ キャッシュ ＋ ロールバック） | 発行 → 読み込み → 戻す、が往復する |
| 第 5 段 | **発行の画面**（`portal-resource-bar`。検証結果と差分の表示） | 検証に落ちた重ねを発行できないこと |
| 第 6 段 | **雛形の照合**（発行時に Docs 本文とプレースホルダーを突き合わせる） | プレースホルダーの無い雛形で発行が落ちること |

第 1・2 段はツールが無くても書けます。**土台のルールの中身**（告示の別表の転記）は
ツール側の作業で、[contract-formatter.md](contract-formatter.md) の Phase 2 にあります。

## 14. 決めごとの一覧

| # | 決めごと | なぜ | 節 |
| --- | --- | --- | --- |
| 1 | **告示・法令に書いてあることはリポジトリに置く**（隠さない） | 公開情報を隠しても得るものがなく、**CI で転記を守れなくなる** | §1 |
| 2 | **事務所が決めたことだけを Drive に置き、差し込む** | ここが事務所の中身そのもの | §1・§6 |
| 3 | 実行時は Firestore の発行済み版だけを読み、Drive を見ない | 編集途中が本番へ出ない。速い。Drive の障害で止まらない | §4 |
| 4 | 発行の単位はフォルダ全体、版はハッシュ 1 つ | 再現するときに指すものが 1 つで済む | §4 |
| 5 | 発行できるのは Drive の編集権限を持つ人 | 権限の仕組みを portal に作らない | §4 |
| 6 | 検証に落ちた内容は発行できない | 壊れた設定が本番に出る経路を無くす | §4 |
| 7 | **告示による算定額より前は差し替えられない。重ねは必ずその後ろに出る** | 書面で分けて印字するものを、計算でも分けて持つ | §6 |
| 8 | **土台が必須にしている記載事項は緩められない**（厳しくするのは可） | 法定記載事項を落とした書面を作れないようにする | §6 |
| 9 | 数は有理数で持ち、丸めは `round` の手順でだけ起きる | 端数の消える位置が定義に書いてある状態にする | §7 |
| 10 | 評価器に既定値を持たない | どこから来たか分からない値が金額に混ざらない | §7 |
| 11 | 土台は公開 CI、重ねは発行時の自己テストで守る | 守れる場所が違う | §8 |
| 12 | 生成物に土台の版と重ねのハッシュを埋め、再計算しない | 過去の書類の再現性 | §9 |
| 13 | 重ねはビルドに焼き込まず、認証の要る API から配る（土台は焼き込んでよい） | 静的ファイルはサインインしていない相手にも配られる | §5 |
| 14 | 既存ツールの定義は移さない | 公開されている様式・公刊物の計算法を隠しても得るものがない | §12 |
